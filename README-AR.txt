تغييرات أمان YAWMAK فقط — بدون أي تعديل على التصميم أو الواجهات

الملفات:
1) src/app/api/admin/route.ts
   - تشديد تغيير صلاحيات المستخدمين: المالك لا يمكن تعديل دوره، ولا يمكن للمسؤول تغيير دوره بنفسه.
   - إبطال جلسات المستخدم بعد تغيير دوره حتى يعاد تحميل صلاحياته من قاعدة البيانات عند تسجيل الدخول.
   - مراجعة الاشتراك أصبحت داخل معاملة قاعدة بيانات واحدة، مع قفل سجل الاشتراك والدفع، والتحقق من أن الطلب والدفع ما زالا قيد المراجعة.
   - لا يقبل قرار مراجعة غير approve أو reject.
   - التحقق من رمز الباقة والسعر قبل تحديث الأسعار.

2) src/app/api/memberships/route.ts
   - إلغاء الاشتراك يحدث داخل معاملة واحدة ويعيد الحساب إلى FREE، ويلغي الطلبات المعلقة والاشتراكات النشطة فقط.
   - طلب الاشتراك لا يفعّل المزايا بنفسه؛ يظل pending_review حتى يعتمد الدفع من الإدارة.

3) supabase/migrations/003_admin_membership_security.sql
   - قيود قاعدة بيانات على الأدوار والباقات وحالات الاشتراك والدفع والمبالغ وفترة الاشتراك.
   - فهارس لتسريع عمليات مراجعة الاشتراكات والمدفوعات.

طريقة التطبيق:
- ارفع الملفات الثلاثة إلى نفس المسارات في مشروع YAWMAK واستبدل النسخ القديمة.
- افتح SQL Editor في قاعدة PostgreSQL/Supabase التي يستخدمها المشروع عبر DATABASE_URL.
- نفّذ محتوى ملف 003_admin_membership_security.sql مرة واحدة.
- بعدها اعمل Commit و Push إلى GitHub وانتظر نشر Vercel.

مهم للأمان:
- DATABASE_URL لازم يظل Environment Variable على Vercel فقط، ولا يوضع في NEXT_PUBLIC_* ولا داخل ملفات المشروع أو GitHub.
- لا تمنح المتصفح اتصالًا مباشرًا بقاعدة البيانات. كل عمليات تغيير role أو membershipPlan يجب أن تمر عبر API الخادمي المحمي بالجلسة والصلاحية.
- لا يوجد نظام مضمون ضد كل الاختراقات؛ هذه التغييرات تقفل مسارات تصعيد صلاحيات ومراجعة اشتراكات غير سليمة، لكنها لا تغني عن حماية حساب Vercel وقاعدة البيانات ومراجعة إعدادات الاستضافة.
- ملف SQL يضيف قيودًا؛ إذا كانت هناك بيانات قديمة مخالفة للقيم المسموحة فسيرفض PostgreSQL تنفيذ الترحيل ويجب مراجعة تلك البيانات قبل إعادة المحاولة.

لم يتم تغيير أي CSS أو مكونات واجهة أو تصميم.

تحديث أمان YAWMAK — حماية تسجيل الدخول وRate Limit
بدون أي تعديل على التصميم أو ملفات CSS أو مكونات الواجهة.

الملفات داخل الحزمة:
1) src/lib/security.ts
   - جعل عداد Rate Limit عملية UPSERT ذرية واحدة لتقليل تجاوز الحد بسبب الطلبات المتزامنة.
   - فشل مغلق: إذا تعذر الوصول إلى مخزن حدود المحاولات، لا يسمح لمسارات المصادقة بالاستمرار بلا حدود.
   - بصمة الحد تعتمد على عنوان الاتصال الممرر من الاستضافة مع مفتاح إضافي، دون الاعتماد على User-Agent.

2) src/app/api/auth/login/route.ts
   - حد مستقل للاتصال: 30 محاولة خلال 15 دقيقة.
   - حد مستقل لكل رقم حساب: 8 محاولات خلال 15 دقيقة.
   - إرجاع HTTP 429 و Retry-After عند تجاوز الحد.
   - رسائل الخطأ لا تكشف هل رقم الهاتف مسجل أم لا.

3) src/app/api/admin/route.ts و src/app/api/memberships/route.ts
   - تشديد إدارة الأدوار ومراجعة الاشتراكات وإلغاء الاشتراك كما في تحديث الأمان السابق.

4) supabase/migrations/003_admin_membership_security.sql
   - قيود تحقق على الأدوار والباقات وحالات الاشتراك والمدفوعات والمبالغ والفترات.

5) supabase/migrations/004_auth_rate_limit_hardening.sql
   - فهرس لتسهيل تنظيف سجلات Rate Limit المنتهية وقيد يمنع العدادات السالبة.

طريقة التركيب:
- خذ نسخة احتياطية من المشروع أولًا.
- استبدل الملفات الموجودة داخل src بنفس المسارات.
- نفّذ migration رقم 003 مرة واحدة إذا لم تكن نفذته سابقًا.
- نفّذ migration رقم 004 مرة واحدة في Supabase SQL Editor.
- لا تعِد تنفيذ 003 إذا كان قد نُفذ بنجاح؛ قيوده قد تكون موجودة بالفعل.
- ارفع التعديلات إلى GitHub وانتظر Vercel.

ملاحظات تشغيل مهمة:
- يوجد Rate Limit حاليًا أيضًا في التسجيل واستعادة الحساب؛ لأنهما يستخدمان checkRateLimit المشترك، أصبح فشل قاعدة البيانات فيهما مغلقًا كذلك.
- هذا التحديث لا يضيف CAPTCHA ولا يغير تجربة الواجهة.
- لا ترسل DATABASE_URL أو كلمات المرور أو مفاتيح Supabase لأي شخص، ولا تضعها في GitHub أو متغيرات NEXT_PUBLIC_*.
- يجب أن تكون DATABASE_URL على Vercel سرية وبمستخدم قاعدة بيانات محدود الصلاحيات قدر الإمكان، وليس superuser أو BYPASSRLS عند إعداد ذلك بشكل متوافق مع التطبيق.
- لا يوجد ضمان أن أي نظام مستحيل الاختراق. يلزم اختبار النشر ومراجعة بقية APIs وإعدادات الاستضافة.

التحقق:
- لم يتم تشغيل Build كامل على هذه البيئة لعدم توفر تثبيت dependencies للمشروع.
- اختبر تسجيل الدخول الصحيح والخاطئ، تجاوز المحاولات، التسجيل، استعادة الحساب، لوحة الإدارة ومراجعة الاشتراكات بعد النشر.
